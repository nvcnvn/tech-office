# Data Model: Voice Communication Support

## Overview

Voice communication adds a new `voice` schema for call lifecycle and voice-message metadata, plus small chat timeline extensions so system call events and voice messages render alongside existing text messages. All tenant-owned tables use `organization_id` as the leading primary-key and unique-index column for Citus compatibility.

## Existing Tables Extended

### `chat.message`

Purpose: Continue to be the conversation timeline source for text messages, voice messages, call announcements, and completed call record rows.

New fields:
- `message_kind text NOT NULL DEFAULT 'text'`: allowed values `text`, `voice`, `system`.
- `system_event_type text NULL`: allowed values when `message_kind = 'system'`: `voice_call_started`, `voice_call_ended`, `voice_call_missed`, `voice_call_cancelled`.
- `metadata jsonb NOT NULL DEFAULT '{}'::jsonb`: structured UI metadata such as `callId`, `voiceMessageId`, `durationMs`, `artifactStatus`, and `joinAction`.

Validation rules:
- `message_kind = 'voice'` requires a corresponding `voice.voice_message` row and at least one file ID after upload confirmation.
- `message_kind = 'system'` requires `system_event_type` and must be created by server logic, not by user-supplied send-message payloads.
- User-authored text messages keep the default `text` kind.

## New Tables

### `voice.call_session`

Purpose: Authoritative business record for one live or completed voice call attached to a chat channel.

Fields:
- `organization_id uuid NOT NULL`
- `id uuid DEFAULT uuidv7()`
- `channel_id uuid NOT NULL`: references `chat.channel(organization_id, id)`; direct messages and task chats are represented by existing channel types.
- `initiator_employee_id uuid NOT NULL`: references `organization.employee(organization_id, id)`.
- `livekit_room_name text NOT NULL`: opaque room name generated by backend.
- `state text NOT NULL`: `ringing`, `active`, `ending`, `ended`.
- `outcome text NULL`: `answered`, `missed`, `declined`, `cancelled`, `completed`.
- `recording_policy text NOT NULL DEFAULT 'not_allowed'`: `not_allowed`, `allowed`, `required`.
- `recording_status text NOT NULL DEFAULT 'unavailable'`: `unavailable`, `pending`, `processing`, `ready`, `failed`.
- `transcript_status text NOT NULL DEFAULT 'unavailable'`: `unavailable`, `pending`, `processing`, `ready`, `failed`.
- `started_at timestamptz NOT NULL DEFAULT now()`
- `answered_at timestamptz NULL`
- `ended_at timestamptz NULL`
- `ended_by_employee_id uuid NULL`: references `organization.employee(organization_id, id)` when user-ended.
- `ended_reason text NULL`: human-readable operational reason or normalized code.
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Keys and indexes:
- Primary key: `(organization_id, id)`.
- Unique active-call guard: unique `(organization_id, channel_id)` where `state IN ('ringing', 'active', 'ending')`.
- Index: `(organization_id, channel_id, started_at DESC)` for room history.
- Index: `(organization_id, state, updated_at DESC)` for cleanup/reconciliation.

Validation rules:
- Only one active/ringing/ending call can exist per channel.
- `outcome` is required when `state = 'ended'`.
- `answered_at` is set when the second participant joins or when a group call has at least one non-initiator participant join.
- `ended_at` is required when `state = 'ended'`.
- LiveKit tokens are never stored; they are generated on demand after membership checks.

### `voice.call_participant`

Purpose: Per-employee call participation history and live reconciliation state.

Fields:
- `organization_id uuid NOT NULL`
- `id uuid DEFAULT uuidv7()`
- `call_session_id uuid NOT NULL`: references `voice.call_session(organization_id, id)`.
- `employee_id uuid NOT NULL`: references `organization.employee(organization_id, id)`.
- `invited_by_employee_id uuid NULL`: references `organization.employee(organization_id, id)`.
- `role text NOT NULL DEFAULT 'participant'`: `initiator`, `participant`.
- `state text NOT NULL`: `invited`, `ringing`, `joining`, `joined`, `disconnected`, `left`, `declined`, `removed`.
- `livekit_identity text NOT NULL`: stable participant identity used in the LiveKit token.
- `joined_at timestamptz NULL`
- `left_at timestamptz NULL`
- `last_seen_at timestamptz NULL`
- `disconnect_reason text NULL`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Keys and indexes:
- Primary key: `(organization_id, id)`.
- Unique participant per call: `(organization_id, call_session_id, employee_id)`.
- Index: `(organization_id, employee_id, updated_at DESC)` for employee call history and ringing state.
- Index: `(organization_id, call_session_id, state)` for active participant counts.

Validation rules:
- A participant row can be created only after ChatLogic confirms room eligibility.
- `joined_at` is required for `joined`, `disconnected`, and `left` states after successful media join.
- `left_at` is required for terminal `left`, `declined`, and `removed` states.

### `voice.call_invitation`

Purpose: Targeted invitation audit record for ongoing group calls.

Fields:
- `organization_id uuid NOT NULL`
- `id uuid DEFAULT uuidv7()`
- `call_session_id uuid NOT NULL`
- `inviter_employee_id uuid NOT NULL`
- `invitee_employee_id uuid NOT NULL`
- `status text NOT NULL DEFAULT 'pending'`: `pending`, `accepted`, `declined`, `expired`, `revoked`.
- `notification_id uuid NULL`: notification row if the invitation produced a persisted alert.
- `created_at timestamptz NOT NULL DEFAULT now()`
- `responded_at timestamptz NULL`
- `expires_at timestamptz NOT NULL`

Keys and indexes:
- Primary key: `(organization_id, id)`.
- Unique pending invite: `(organization_id, call_session_id, invitee_employee_id)` where `status = 'pending'`.
- Index: `(organization_id, invitee_employee_id, status, created_at DESC)`.

Validation rules:
- Invitee must be eligible for the channel at invite time and again at join time.
- Invitation cannot grant chat room access by itself.
- Expired/revoked invitations cannot mint tokens.

### `voice.call_artifact`

Purpose: Async recording and transcript artifacts attached to completed calls.

Fields:
- `organization_id uuid NOT NULL`
- `id uuid DEFAULT uuidv7()`
- `call_session_id uuid NOT NULL`
- `artifact_type text NOT NULL`: `recording`, `transcript`.
- `status text NOT NULL`: `pending`, `processing`, `ready`, `unavailable`, `failed`.
- `file_id uuid NULL`: references `files.file_metadata(organization_id, id)` when ready.
- `mime_type text NULL`
- `duration_ms bigint NULL`
- `storage_bytes bigint NULL`
- `provider text NULL`: `livekit_egress`, `transcription_worker`, or future provider.
- `provider_job_id text NULL`
- `error_code text NULL`
- `error_message text NULL`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Keys and indexes:
- Primary key: `(organization_id, id)`.
- Unique artifact kind per call: `(organization_id, call_session_id, artifact_type)` for the first implementation.
- Index: `(organization_id, status, updated_at)` for async worker reconciliation.

Validation rules:
- `file_id` is required when `status = 'ready'`.
- `error_code` is required when `status = 'failed'`.
- Call record remains visible when artifact status is `unavailable` or `failed`.

### `voice.voice_message`

Purpose: Voice-message upload, idempotency, and playback metadata for a chat timeline message.

Fields:
- `organization_id uuid NOT NULL`
- `id uuid DEFAULT uuidv7()`
- `channel_id uuid NOT NULL`: references `chat.channel(organization_id, id)`.
- `sender_employee_id uuid NOT NULL`: references `organization.employee(organization_id, id)`.
- `message_id uuid NULL`: references `chat.message(organization_id, id)` after the timeline row is posted.
- `file_id uuid NULL`: references `files.file_metadata(organization_id, id)` after upload confirmation.
- `client_deduplication_key text NOT NULL`: generated by the client before upload.
- `status text NOT NULL DEFAULT 'requested'`: `requested`, `uploading`, `posted`, `failed`, `cancelled`.
- `duration_ms bigint NULL`
- `mime_type text NOT NULL`
- `codec text NULL`: expected `opus`, `aac`, or future supported codec.
- `waveform_peaks jsonb NULL`: small normalized playback visualization payload.
- `size_bytes bigint NOT NULL`
- `created_at timestamptz NOT NULL DEFAULT now()`
- `posted_at timestamptz NULL`
- `updated_at timestamptz NOT NULL DEFAULT now()`

Keys and indexes:
- Primary key: `(organization_id, id)`.
- Unique retry/idempotency guard: `(organization_id, channel_id, sender_employee_id, client_deduplication_key)`.
- Unique posted message: `(organization_id, message_id)` where `message_id IS NOT NULL`.
- Index: `(organization_id, channel_id, created_at DESC)`.

Validation rules:
- Sender must have permission to post in the channel at request and confirmation time.
- `posted` requires `message_id`, `file_id`, and `duration_ms`.
- `cancelled` must not create a `chat.message` row.
- Retrying confirm with the same deduplication key returns the existing posted voice message instead of creating a duplicate.
- Allowed MIME types are limited to configured audio types such as `audio/webm`, `audio/ogg`, `audio/mp4`, or platform-specific equivalents that the backend accepts.

## Derived/External State

### LiveKit Room

Not stored as a business entity beyond `voice.call_session.livekit_room_name`. The backend mints scoped tokens with room join/publish permissions only after room membership is verified. LiveKit webhooks reconcile participant and egress state back into Postgres.

### Active Call SSE State

Not a separate durable table. Active state is derived from `voice.call_session.state` and fanned out via notification live-only events. Clients also call `GetActiveVoiceCall` when opening a room so reloads and missed SSE events recover current state.

## State Transitions

### Call Session

```text
ringing -> active       when a non-initiator joins or group call is accepted
ringing -> ended        when cancelled, declined by all recipients, or unanswered timeout expires
active  -> ending       when final leave, explicit end, or LiveKit room-finished webhook starts reconciliation
ending  -> ended        when participant/artifact finalization completes or timeout forces closure
active  -> ended        allowed for simple explicit end path when no async reconciliation is pending
```

Terminal outcomes:
- `answered`: call was accepted but may not have completed normally yet.
- `completed`: active call ended after at least two participants joined.
- `missed`: no eligible recipient joined before timeout.
- `declined`: invited recipient(s) declined before anyone joined.
- `cancelled`: initiator cancelled before the call was answered.

### Participant

```text
invited -> ringing -> joining -> joined
joined -> disconnected -> joined
joined -> left
ringing -> declined
invited/ringing/joining/joined/disconnected -> removed
```

### Voice Message

```text
requested -> uploading -> posted
requested -> cancelled
uploading -> failed -> uploading
uploading -> cancelled
posted is terminal
cancelled is terminal
```

## Constant Synchronization Requirements

The following values must be aligned in schema constraints, Go constants, proto enums or string constants, and frontend TypeScript unions:
- `message_kind`: `text`, `voice`, `system`
- `system_event_type`: `voice_call_started`, `voice_call_ended`, `voice_call_missed`, `voice_call_cancelled`
- `call_session.state`: `ringing`, `active`, `ending`, `ended`
- `call_session.outcome`: `answered`, `missed`, `declined`, `cancelled`, `completed`
- `call_participant.state`: `invited`, `ringing`, `joining`, `joined`, `disconnected`, `left`, `declined`, `removed`
- `call_artifact.status`: `pending`, `processing`, `ready`, `unavailable`, `failed`
- Notification types: `voice_call_incoming`, `voice_call_started`, `voice_call_updated`, `voice_call_ended`
- Policy keys: `chat_voice_call_incoming`, `chat_voice_call_live`, `chat_voice_call_record`
