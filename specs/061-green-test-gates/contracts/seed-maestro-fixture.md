# Contract: `seed-maestro-fixture`

**Surface**: backend CLI command, `backend/cmd/seed_maestro.go`, registered in
`backend/cmd/main.go` alongside `SeedDemoOrgCommand`.

**Covers**: FR-012, FR-013, FR-014, FR-015, FR-016, FR-019

**Modelled on**: `SeedDemoOrgCommand` (`backend/cmd/seed_demo.go`) — same `urfave/cli/v3` shape,
same `database.NewAdminPool` + `config.Get()` connection, same
`GetOrganizationBySubdomain` → reuse-or-register idempotency.

---

## Invocation

```
go run ./cmd seed-maestro-fixture [flags]
```

Run from `backend/` with `DATABASE_URL` set, the same way `seed-demo-org` is run today.

## Flags

| Flag | Default | Meaning |
|---|---|---|
| `--subdomain` | `maestro` | Workspace address. **Rejected if `demo`** (FR-019). |
| `--owner-password` | `MaestroFixture1!` | Primary account's password → `MAESTRO_TEST_PASSWORD` |
| `--owner-pin` | `246810` | Primary account's permanent PIN → `MAESTRO_TEST_PIN` |
| `--worker-password` | defaults to `--owner-password` | Non-privileged account's password |
| `--worker-pin` | `135791` | Non-privileged account's permanent PIN |
| `--signup-password` | `MaestroSignup1!` | Value emitted as `MAESTRO_OWNER_PASSWORD` — *typed by* `onboarding/owner-signup.yaml`, not an existing account |
| `--signup-pin` | `314159` | Value emitted as `MAESTRO_OWNER_PIN`, likewise |

Defaults are chosen so the command needs **no flags** for the documented path (FR-012: "a single
documented command"). Passwords are fixture credentials for a local database and are not secrets;
they are nevertheless overridable so a shared development database can use its own.

## Output contract

This is the part that makes the command usable without a human transcribing ids.

- **stdout** carries *only* the `.env` body: comment lines beginning `#`, and `KEY=VALUE` lines.
  Nothing else. It is directly redirectable:

  ```
  go run ./cmd seed-maestro-fixture > ../frontend/apps/mobile/.maestro/.env
  ```

- **stderr** carries every progress and diagnostic line — "Reusing existing fixture workspace…",
  "Created department…", warnings. A redirect of stdout therefore still shows the operator what
  happened.

This splits from `seed-demo-org`, which prints its human-readable credential block to stdout.
That command's output is meant to be *read* and pasted into store-review notes; this one's output
is meant to be *written to a file*, and mixing log lines into it would corrupt the `.env` on the
very first use. FR-016 asks for "a form that can be written directly"; a clean stdout is that
form.

### stdout shape

```
# Maestro fixture — generated by `go run ./cmd seed-maestro-fixture`
# Seeded 2026-09-12T09:14:22Z against workspace "maestro".
# Re-run the command to refresh; do not hand-edit MAESTRO_TEAM_TASK_ID.

MAESTRO_TEST_SUBDOMAIN=maestro
MAESTRO_TEST_EMAIL=owner@maestro.maestro.invalid
MAESTRO_TEST_PASSWORD=MaestroFixture1!
MAESTRO_TEST_PIN=246810

# onboarding/owner-signup.yaml types these to register a NEW workspace each run.
# They do not name a seeded account.
MAESTRO_OWNER_PASSWORD=MaestroSignup1!
MAESTRO_OWNER_PIN=314159

# feature-tour/worker-tour.yaml needs an account WITHOUT iam.inviteUser. It reads
# MAESTRO_TEST_EMAIL, so run it with these values overriding that pair:
#   make test-mobile-one F=feature-tour/worker-tour \
#     MAESTRO_ENV_FLAGS="-e MAESTRO_TEST_EMAIL=... -e MAESTRO_TEST_PASSWORD=..."
MAESTRO_WORKER_EMAIL=worker@maestro.maestro.invalid
MAESTRO_WORKER_PASSWORD=MaestroFixture1!
MAESTRO_WORKER_LOGIN=maestro-worker
MAESTRO_WORKER_PIN=135791

MAESTRO_TEAM_TASK_ID=019287f4-...-...
MAESTRO_SEARCH_WORD=zarquon
MAESTRO_SEARCH_DOCUMENT_TITLE=Zarquon Closing Procedure
MAESTRO_DIRECTORY_PERSON_WITH_PHONE=Tran
MAESTRO_DIRECTORY_PERSON_NO_PHONE=Okafor
MAESTRO_DIRECTORY_DEPARTMENT=Store Floor
```

**Quoting**: values are emitted **unquoted**. `run-maestro-suite.sh` splits each line at the first
`=` and passes the remainder verbatim as one `-e` argument in a shell array, so a value containing
spaces — `Zarquon Closing Procedure` — is already safe there. The Makefile's `MAESTRO_ENV_FLAGS`
wraps each line in single quotes itself. Adding quotes in the file would therefore produce
`-e 'KEY="value"'` and leak the quotes into the flow. No emitted value may contain a single
quote, a newline or a `=`; the command fails rather than emitting one that does.

## Exit codes

| Code | Condition |
|---|---|
| 0 | Fixture present and current; every value emitted |
| non-zero | Database unreachable, `--subdomain demo`, or any seeding step failed — message on stderr naming the step |

A partial seed must not exit 0. Each account and content group is created inside
`txn.WithTxn`, so a failure leaves no half-built account behind.

## Idempotency contract (FR-013, SC-004)

Running the command twice in a row MUST leave:

- exactly **one** organization at the target subdomain;
- the same accounts, reactivated if a flow deactivated them, with credentials refreshed to the
  flag values;
- the ritual instances recreated relative to a single `seededAt` clock, so "overdue" is still
  overdue and "today" is still today;
- blocks between fixture accounts cleared;
- stdout whose values are unchanged, except `MAESTRO_TEAM_TASK_ID`, which changes when the
  overdue instance is recreated and is therefore emitted every run.

## What this command does NOT do

- It does not create or touch the `demo` workspace, and does not read its content (FR-019).
- It does not seed the nineteen `MAESTRO_CANONICAL_*` / `MAESTRO_NAV_*` /
  `MAESTRO_LINK_PREVIEW_*` values used by flows outside the standing suite (spec Assumption 6).
- It does not write `.maestro/.env` itself. The backend may be running in a container with no
  view of the repository, and a command that writes a host path would be unrunnable there;
  redirecting stdout works from either side.
- It does not delete the workspaces `onboarding/owner-signup.yaml` leaves behind. That is
  `make test-db-purge`'s job.
