# Contract: the `MAESTRO_*` environment surface

**Surfaces**: `frontend/apps/mobile/.maestro/.env` (gitignored, generated),
`frontend/apps/mobile/.maestro/.env.example` (tracked), and the `check-maestro-env` target in
the root `Makefile`.

**Covers**: FR-015, FR-017, FR-018

---

## Required by the standing suite

These thirteen names are read by the 27 flows `frontend/apps/mobile/scripts/run-maestro-suite.sh`
runs. `make test-mobile` MUST NOT launch a flow if any of them is absent or empty.

| Variable | Read by | Produced by |
|---|---|---|
| `MAESTRO_TEST_SUBDOMAIN` | `auth/signin.yaml`, `auth/signin-known-device.yaml` | seeder |
| `MAESTRO_TEST_EMAIL` | both sign-in flows; `projects/create-project.yaml`; `rituals/create-ritual.yaml` | seeder |
| `MAESTRO_TEST_PASSWORD` | `auth/signin.yaml` | seeder |
| `MAESTRO_TEST_PIN` | `auth/signin-known-device.yaml` | seeder |
| `MAESTRO_OWNER_PASSWORD` | `onboarding/owner-signup.yaml` | seeder (a value to type, not an account) |
| `MAESTRO_OWNER_PIN` | `onboarding/owner-signup.yaml` | seeder (likewise) |
| `MAESTRO_TEAM_TASK_ID` | `screens/today.yaml` | seeder |
| `MAESTRO_SEARCH_WORD` | `federated-search.yaml` | seeder |
| `MAESTRO_SEARCH_DOCUMENT_TITLE` | `federated-search.yaml` | seeder |
| `MAESTRO_DIRECTORY_PERSON_WITH_PHONE` | `people/directory-call.yaml`, `compliance/block-from-profile.yaml` | seeder |
| `MAESTRO_DIRECTORY_PERSON_NO_PHONE` | `people/directory-call.yaml` | seeder |
| `MAESTRO_DIRECTORY_DEPARTMENT` | `people/department-members.yaml` | seeder |
| `MAESTRO_WORKER_EMAIL` + `MAESTRO_WORKER_PASSWORD` | `feature-tour/worker-tour.yaml`, by override | seeder |

`MAESTRO_WORKER_LOGIN` and `MAESTRO_WORKER_PIN` are emitted and documented but are **not**
required by the check: no standing-suite flow reads them, and a check that demands more than the
suite needs is a check that blocks a valid run.

## Generated per run, never seeded

| Variable | Generated by |
|---|---|
| `MAESTRO_RUN_ID` | `run-maestro-suite.sh` (a timestamp) or the Makefile's `MAESTRO_RUN_ID` |
| `MAESTRO_DEV_CLIENT_URL` | `scripts/resolve-ip.sh`, via the runner or the Makefile |

`MAESTRO_RUN_ID` **must not** be pinned to a value in `.env`. `onboarding/owner-signup.yaml`
derives a new workspace address from it, so a fixed value makes the second run collide on the
address the first claimed. The runner already skips keys with an empty value
(`run-maestro-suite.sh`: `[[ "${line#*=}" == "" ]] && continue`), so `MAESTRO_RUN_ID=` in the file
is harmless — but the seeder does not emit the key at all.

## Outside the standing suite — documented, not seeded

`MAESTRO_CANONICAL_TASK_LINK`, `MAESTRO_CANONICAL_TASK_OPEN_LINK`,
`MAESTRO_CANONICAL_ACCESS_DENIED_OPEN_LINK`, `MAESTRO_CANONICAL_NOT_FOUND_OPEN_LINK`,
`MAESTRO_CANONICAL_TASK_READY_TEXT`, `MAESTRO_CANONICAL_PREVIEW_CHANNEL_ID`,
`MAESTRO_CANONICAL_TASK_TITLE`, `MAESTRO_CANONICAL_TASK_IDENTIFIER`,
`MAESTRO_LINK_PREVIEW_DOCUMENT_LINK`, `MAESTRO_LINK_PREVIEW_DOCUMENT_TITLE`,
`MAESTRO_NAV_TASK_PROJECT_ID`, `MAESTRO_NAV_TASK_ID`, `MAESTRO_NAV_CHANNEL_ID`.

These belong to `canonical-resource-links.yaml`, `chat-link-previews.yaml` and
`navigation-shared-routes-smoke.yaml`, which are run individually against purpose-built
fixtures. `.env.example` keeps them, under a heading that says so plainly, and the existing
`check-maestro-canonical-env` / `check-maestro-link-preview-env` targets keep guarding them for
the single-flow invocations that need them.

## `.env.example` contract (FR-017)

The tracked example MUST:

1. name **every** variable any flow in the repository reads, standing-suite or not;
2. group them under headings that say which flows read each group and whether the standing suite
   needs them;
3. state, at the top, that the standing-suite values are produced by
   `go run ./cmd seed-maestro-fixture` and how to redirect its output into `.env`;
4. carry no real credential — it is tracked, and placeholders are what it is for.

## Fail-fast contract (FR-018)

`check-maestro-env` grows the required-variable loop that
`check-maestro-canonical-env` and `check-maestro-link-preview-env` already use. On a missing or
empty value it prints the missing names **and the command that produces them**, then exits 1 —
before `run-maestro-suite.sh` launches the first flow:

```
✗ Missing Maestro fixture vars in frontend/apps/mobile/.maestro/.env: MAESTRO_TEAM_TASK_ID MAESTRO_SEARCH_WORD
  Produce them with:
    cd backend && go run ./cmd seed-maestro-fixture > ../frontend/apps/mobile/.maestro/.env
```

The existing "file not found" branch gains the same instruction, replacing today's
"Copy from .env.example and fill in credentials" — which is precisely the manual arrangement this
feature exists to remove.

The check tests for a **non-empty** value (`grep -q "^VAR=."`), not merely a present key. The
existing canonical and link-preview checks use `grep -q "^$$var="`, which passes on a bare
`VAR=`; since the runner then skips that key, an empty value produces exactly the confusing
mid-suite assertion failure FR-018 forbids. The new check therefore requires at least one
character, and the two existing checks are tightened the same way in passing — a one-character
diff each, and they are wrong in the same way.
