# Bug Fix: Delivery Status Not Updated on Mark As Read

## Issue
When notifications were marked as read, the `delivery_status` column remained `'pending'` instead of being updated to `'delivered'`, and `delivered_at` timestamp was not set.

## Root Cause
The SQL queries (`MarkNotificationAsRead`, `MarkNotificationsAsReadBatch`, `MarkAllBeforeTimestampAsRead`) were only updating `read_status` and `read_at` fields, without updating the delivery tracking fields.

## Changes Made

### 1. SQL Queries (`backend/database/scripts/notification.query.sql`)

Updated all three mark-as-read queries to:
- Set `delivery_status = 'delivered'`
- Set `delivered_at` using CASE statement (Citus-compliant)
- Use parameterized timestamps instead of `now()` (Citus requirement)

**Example (MarkNotificationsAsReadBatch)**:
```sql
UPDATE notification.notification_recipient
SET read_status = true,
    read_at = $4,
    delivery_status = 'delivered',
    delivered_at = CASE WHEN delivered_at IS NOT NULL THEN delivered_at ELSE $4 END,
    updated_at = $4
WHERE id = ANY($1::uuid[])
  AND employee_id = $2
  AND organization_id = $3
  AND read_status = false;
```

### 2. Go Code (`backend/internal/notification/notification.go`)

- Added `time` import
- Updated both RPC handlers to pass current timestamp as `ReadAt` parameter:

```go
now := time.Now()
err = s.Queries.MarkNotificationsAsReadBatch(ctx, s.TenantPool, &database.MarkNotificationsAsReadBatchParams{
    Column1:        recipientIDs,
    EmployeeID:     employeeID,
    OrganizationID: organizationID,
    ReadAt:         pgtype.Timestamptz{Time: now, Valid: true},
})
```

### 3. Schema Comments (`backend/database/scripts/schema.sql`)

Updated comments to document the auto-update behavior:

```sql
COMMENT ON COLUMN notification.notification_recipient.delivery_status IS 'pending = awaiting delivery, delivered = sent via SSE or fallback, failed = all delivery attempts failed. Auto-updated to delivered when notification is marked as read.';

COMMENT ON COLUMN notification.notification_recipient.read_status IS 'Whether the notification has been read by the employee. When set to true, delivery_status is automatically updated to delivered.';
```
